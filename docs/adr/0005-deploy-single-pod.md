# ADR 0005 — деплой MVP: один под, образ без реестра, бэкапы на хосте

**Дата:** 2026-11-02 · **Статус:** принято · **Этап:** 5

## Контекст

Сервис — одиночный процесс без входящего HTTP, с long polling Telegram, очередью в PostgreSQL и записью
файлов в базу знаний. Кластер — single-node k3s на hector, без реестра образов и без внешнего CI.
Требования §13.2: одна реплика, лимит 1536 Mi, PVC 5 Gi, hostPath внешней базы для владельца,
`pg_dump` по cron с хранением 7 дней.

## Решения

1. **`replicas: 1` + `strategy: Recreate`.** Второй под забирает апдейты (`409 getUpdates`) и ломает
   внутрипроцессную блокировку записи по `knowledge_base.id` (NFR-4). Recreate гарантирует, что старый
   под завершился до старта нового: окно простоя — секунды, зато нет двух поллеров.

2. **Образ без реестра.** Jar собирается Gradle на хосте, образ — `podman build` (temurin 25 JRE + python3
   для линтера), затем `k3s ctr images import`. Реестр в домашнем кластере — лишняя сущность; версия
   образа (`0.1.0`) фиксируется тегом, откат = импорт предыдущего тега.

3. **Проб нет.** HTTP-сервера нет по NFR-1, а `exec`-проба «жив ли поллер» неотличима от зависания:
   поллер молчит, когда нет апдейтов. Живость подтверждается строками в БД (`telegram_update`,
   `processing_job`) и отсутствием `409`/backoff в логе; падение процесса k8s видит сам.

4. **Линтер базы остаётся гейтом и в поде.** В образ ставится python3+PyYAML, скрипт монтируется
   ConfigMap из `~/.hermes/scripts/agora_lint.py` (host — единственный источник истины, копия в git не
   хранится). Иначе под писал бы заметки, которые отклоняет реальный линтер, и ломал бы sync базы.

5. **Секреты — только Secret, создаётся вручную** из `~/.hermes/secrets.env`. В git — `secret.example.yaml`
   без значений. Сервис получает их `envFrom`, ключи API и токен бота не логируются (NFR-6).

6. **Бэкапы — user-таймер systemd на хосте**, а не CronJob: `pg_dump` и tar внутренних баз выполняются
   через `kubectl exec`, результат кладётся на `/mnt/hdd/backups/uzelok` (диск 2 ТБ), хранение 7 дней.
   CronJob с hostPath потребовал бы второй копии расписания и прав на узел; таймер проще и виден в
   `systemctl --user list-timers`.

## Последствия

- Простой при деплое — от нескольких секунд (Recreate); во время рестарта апдейты Telegram ждут на
  стороне Bot API (long polling offset не теряется).
- `/var/lib/uzelok` живёт на `local-path` (корневой LVM, не `/mnt/hdd`): 5 Gi хватает артефактам и
  внутренним базам MVP; при росте — переезд на PV поверх `/mnt/hdd`.
- Хранение 7 дней — без offsite-копии; вопрос облачного бэкапа остаётся открытым.
- ConfigMap линтера обновляется `scripts/deploy.sh`; при правке линтера на хосте нужен повторный деплой,
  иначе в поде останется старая версия.
