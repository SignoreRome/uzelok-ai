# Uzelok

Персональный сервис обучения. Материал (фото рукописного конспекта, текст, документ `.txt`/`.md`) или
название темы превращается в структурированный Markdown-конспект: пользователь получает превью в
Telegram, подтверждает — и заметка появляется в Obsidian-совместимой базе знаний.

Целевая эксплуатация: один под в single-node k3s на домашнем сервере `hector`, единицы заметок в день.

## Статус

| Этап | Состояние |
| :--- | :--- |
| ТЗ MVP | готово, `docs/TZ_MVP.md` (v1.3) |
| Этап 1 — скелет приложения, Flyway `V1`, ArchUnit | в работе |
| Этап 2 — знание: рендер, таксономия, валидатор | не начат |
| Этап 3 — Telegram, LLM, пайплайн | не начат |
| Этап 4 — внутренняя база, `/export` | не начат |
| Этап 5 — деплой в k3s, бэкапы, DoD | не начат |

## Что в MVP

- Telegram-бот в режиме Long Polling (входящих портов нет).
- Распознавание фото → тезисы → конспект; текст и документы без OCR.
- Превью с кнопками `Сохранить` / `Перегенерировать` / `В _Inbox` / `Отмена`.
- Запись в две базы: внешняя Obsidian-база владельца и внутренняя, созданная сервисом.
- Идемпотентность на всех шагах: повторная доставка апдейта и рестарт пода не создают дублей.
- Журнал LLM-вызовов со стоимостью, аудит действий, квоты и дневной бюджет.

Вне MVP: FSRS, RAG-поиск, голосовые сообщения, веб-интерфейс, OIDC, брокер сообщений. Полный список
границ — раздел 2 ТЗ.

## Стек

- Java 25 (LTS, toolchain), Gradle 9 (Kotlin DSL)
- Spring Boot 4.1.2, Spring AI 2.0.2 (`spring-ai-starter-model-openai`)
- `org.telegram:telegrambots-longpolling` + `telegrambots-client` 10.3.0
- PostgreSQL + Flyway 12 (BOM Spring Boot), JDBC (без JPA)
- Тесты: JUnit 5, Testcontainers, ArchUnit 1.4.1
- Деплой: k3s, Jib 3.5.4

Сервис не поднимает HTTP-сервер (`spring.main.web-application-type=none`) и **не выполняет git-операций
ни в одной базе знаний**: внешнюю коммитит её собственный процесс синхронизации, внутренняя — обычный
каталог, который выгружается командой `/export`.

## Сборка и тесты

Нужен JDK 25 (проверено на Temurin 25.0.5). На `hector` он лежит вне пакетов системы:

```bash
export JAVA_HOME="$HOME/.local/share/jvm/jdk-25.0.5+8"
export PATH="$JAVA_HOME/bin:$PATH"

./gradlew build          # компиляция + тесты
./gradlew test           # только тесты
./gradlew bootJar        # исполняемый jar
```

Тесты с Testcontainers требуют работающий Podman или Docker (`DOCKER_HOST` для rootless podman).

## Структура

```text
docs/TZ_MVP.md      ТЗ MVP (v1.3) — единственный источник требований
docs/adr/           архитектурные решения по мере реализации
deploy/k8s/         манифесты namespace, deployment, networkpolicy, pvc
scripts/            e2e-dry-run.sh, pg-dump.sh
src/main/java/uzelok/
  domain/           модель и порты, без Spring, SQL и сети
  pipeline/         состояния job, воркер, шаги
  knowledge/        рендер заметки, таксономия, валидатор, хранилища
  telegram/         long polling, роутинг апдейтов, превью
  llm/              structured output, роутер моделей, учёт стоимости
  persistence/      JDBC-репозитории
  config/           свойства и конфигурация Spring
src/main/resources/ application.yml, db/migration, prompts, vault-template
```

Правила зависимостей между пакетами проверяются тестом `LayerRulesTest` (ArchUnit), см. раздел 7.1 ТЗ.

## Код и AI

Код, тесты и документация в этом репозитории **написаны AI-агентом** (`Hector AI` через OpenCode CLI)
под ревью и приёмку владельца. Коммиты подписаны `Hector AI`. Архитектурные решения и критерии приёмки
принадлежат владельцу; ревью кода выполняется отдельной моделью до мержа.
